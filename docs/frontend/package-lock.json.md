# package-lock.json


## Overview

`package-lock.json` is an automatically generated file that records the **exact versions of all installed dependencies** in the project.

Its main purpose is to ensure that:
- every developer installs **exactly the same dependency versions**
- the project behaves consistently across environments.

---

## Why this file exists

In `package.json` you have:

```json
"react": "^19.2.4"
```

This means:

`install any compatible version (e.g. 19.2.5, 19.3.0, etc.)

But in `package-lock.json` you get:

```json
"react": {
  "version": "19.2.4"
}
```

This **locks the exact version**.

---

## Key idea

`package.json` = what you want
`package-lock.json` = what you actually installed

---

## Structure overview

We can divide **package-lock.json** into main parts:

### 1. Root metadata

```json
{
  "name": "realtimechatfe",
  "version": "0.0.0",
  "lockfileVersion": 3,
  "requires": true,
```

#### Meaning:
| field            | description                                |
|------------------|--------------------------------------------|
| name             | project name                               |
| version          | project version                            |
| lockfileVersion  | format version of lock file (npm internal) |
| requires         | indicates dependencies are used            |

---

### 2. `packages` section (most important)

```json
"packages": {
```

This is the **core of the file.**

It describes **every installed package.

---

## Special case: root package

```json
"": {
  "name": "realtimechatfe",
  "version": "0.0.0",
  "dependencies": {...},
  "devDependencies": {...}
}
```

### What is `""`?

It represents:
`your project root (main application)`

So this is basically:

your `package.json` copied into the lock file

---

## Installed packages

Example

```json
"node_modules/@babel/code-frame": {
  "version": "7.29.0",
  "resolved": "...",
  "integrity": "...",
  "dev": true,
  "dependencies": {...}
}
```

### What each field means

`version` - exact installed version (locked)

```json
"version": "7.29.0"
```

---

`resolved` - where the package was downloaded from

```json
"resolved": "https://registry.npmjs.org/..."
```

---

`integrity` - hash used to verify package integrity (security)

```json
"integrity": "sha512-..."
```

---

`dev` - tells if package comes from:
- `devDependencies` → true
- `dependencies` → false / missing

```json
"dev": true
```

---

`dependencies` - dependencies of that package (nested dependencies)

```json
"dependencies": {
  "@babel/helper-validator-identifier": "^7.28.5"
}
```

---

`engines` - required Node.js version

```json
"engines": {
  "node": ">=6.9.0"
}
```

---

`peer` - indicates **peer dependency context** (used by libraries)

```json
"peer": true
```

---

## What this structure represents

This file is basically:

| a full **dependency tree**

Example:

```bash
your app
 ├─ react
 ├─ vite
 └─ eslint
      └─ @babel/core
           └─ @babel/parser
```

And every node in this tree is described in `packages`.

---

## Key concepts

### 1. Deterministic installs

Thanks to `package-lock.json`:

`npm install`

always gives the **same result**

---

### 2. Transitive dependencies

You installed:

```json
"eslint"
```

But lock file shows:

```
eslint → babel → parser → helpers → ...
```

dependencies of dependencies

---

### 3. You should NOT edit this file manually

`❌ never edit package-lock.json by hand`

It is:
- auto generated
- managed by npm

---

### 4. When it changes

It updates when you run:

```
npm install
npm uninstall
npm update
```

---

## Summary:

`package-lock.json` stores the exact versions and full dependency tree of all installed packages to ensure consistent and reproducible installations.
